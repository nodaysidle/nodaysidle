# AGENTS.md: rules for coding agents in this repository

These rules override your defaults. Read them before changing anything here.

## The artifact

`README.md` is generated by `scripts/build.mjs`. Never edit it by hand, never
hand-type a version, count, or date into it. Change `data/apps.json`,
`data/privacy.json`, or the script, then rebuild. If you find yourself editing
README.md directly, stop: you are in the wrong file.

## Truth

- Never fabricate data, commands, or test output. If you did not run it, you do
  not know it.
- Anything the build cannot verify renders as UNKNOWN. Preserve that behavior;
  never replace an UNKNOWN with a guess, a hardcoded value, or a silent removal.
- If a source disagrees with the registry, report the disagreement. Do not pick
  the value that looks better.

## Done

- Done means verified live: the build ran, the Actions run passed, and the
  rendered page was checked at 1280 px and in GitHub mobile. A push is not done.
  Passing locally is not done. Until then, the work is UNKNOWN.
- The build's refusal rule stays: total source failure must exit non-zero so CI
  commits nothing. Never weaken it to make a red job green.

## Scope

- PR 1 (deterministic core), PR 2 (generated SVG layer), and PR 3 (retire the old
  design) are complete. PR 4 (The Idle Drum) is in progress; see TASKS.md. Do not
  skip ahead in the same PR.
- Use the design tokens in TRD.md exactly. Signal color is used for the stylus
  (today) and verified-live markers only. Radius 0 applies to every rectangle;
  circles are allowed only for the stylus and the live-demo ring. Two subtle CSS
  animations inside the SVG are allowed (the stylus pulse and the live ring), both
  disabled under `prefers-reduced-motion`. Still forbidden: gradients, glows,
  rounded rectangles, iconography inside cards, any accent color beyond the
  tokens.
- Minimal dependencies. Node 22 plus `opentype.js` only, for outlining fonts at
  build time; do not add other packages.
- Never run destructive actions (deletes, force-pushes, releases, production
  deploys) without explicit approval from Alan.

## Communication

- Reply in English. Short by default; detail only when it matters.
- Lead with the answer. No filler, no restating the request.
- Report failures as: exact error, cause, proposed fix, verification step.
  Then stop and let Alan decide how to proceed.
- If you do not know something, ask. Never guess.
