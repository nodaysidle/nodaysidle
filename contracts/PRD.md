# PRD: NODAYSIDLE Profile Redesign

Source of truth for product behavior. Build to this document; the TRD defines how.

## Product

One page: the README of `nodaysidle/nodaysidle`, rendered at github.com/nodaysidle.
Generated by `scripts/build.mjs`, committed by CI, rebuilt daily.

## Page sections, in order

1. The Idle Drum. One generated strip-chart recorder (`assets/drum.svg`) replacing
   the separate header and status strip:
   - Masthead: the wordmark NODAYSIDLE, the studio line ("Independent software
     studio. Deterministic, privacy-first software for Linux."), and a log stamp
     with the build date and chart scale.
   - Four counters: public repository count, apps shipped, days since the newest
     release, telemetry endpoint count.
   - Chart: left edge is today, x axis runs into the past (70-day window, widened
     in steps of 10 when an app's gap is larger). A red line marks 60 days;
     everything past it is the dormant zone.
   - CH-00: one trace with a spike per release (taller when several apps released
     on the same day) and a bracket naming the longest flat stretch between
     releases.
   - CH-T: the telemetry channel, a flat line labeled with the telemetry endpoint
     count from the registry. It makes no claim about history.
   - App channels: one channel per app, newest release first. Line length is the
     gap, color is the privacy class, and a ring marks a demo that answered 200 at
     build time. A null gap is drawn as a dashed pen lift labeled UNKNOWN, never a
     guess.
   - Legend.
2. Flagship loupe. Kureksistant (`assets/flagship.svg`), presented as a magnified
   strip of its own channel (window: 14 days, or gap + 2 if larger), with its
   name, generated version, release date, privacy class, and legend. Exactly one
   flagship.
3. Release ledger. One Markdown table row per app: name, version, release date,
   gap in days, platform, demo state, privacy class. Sorted newest first. Apps
   older than 60 days are tagged dormant.
4. Method. The contract chain 01 IDEA, 02 PRD, 03 ARD, 04 TRD, 05 TASKS plus
   AGENTS.md, with the caption that nothing is called done until it runs live.
5. Privacy matrix. Three classes: Stays on your machine, Cloud calls with your
   own keys, Public data only. Each app appears exactly once, in the class that
   matches its repository README. A detail table below carries the verified
   privacy line per app.
6. Footer. Site, GitHub, email, last build date.

## Data rules

- The registry (`data/apps.json`) is the only human-maintained input for app facts.
- Versions come from the GitHub Releases API; web apps show "web" with their launch
  date from the apps site; the site data is the last-resort fallback for repos
  without releases.
- The gap column is computed against the build date at generation time.
- Demo URLs are checked at build: 200 renders LIVE, anything else renders UNKNOWN.
- The telemetry count is the sum of the registry telemetry flags; each flag must
  match the app's repository README.

## Error behavior

- Any unverifiable value renders as UNKNOWN in place. Nothing is silently removed.
- If every version is UNKNOWN or the repository count fails, the build exits
  non-zero and CI commits nothing. `ALLOW_UNKNOWN=1` opts a local preview out.

## Acceptance criteria

1. Every number on the page is traceable to `data/apps.json`, `data/privacy.json`,
   or a GitHub API response. Zero hand-typed versions, counts, or dates in the output.
2. CI regenerates the page at least once per day; maximum staleness is 24 hours.
3. Every demo link is checked at build; failures render as UNKNOWN, not removal.
4. Each app appears exactly once in the privacy matrix, classed per its README.
5. The ledger gap column recomputes against the build date on every run.
6. The telemetry count is derived from the registry, not asserted in copy.
7. SVG phase: all SVG text outlined to paths; rendering identical across viewers.
8. The page is verified live at 1280 px and in GitHub mobile rendering before any
   pull request is called done. Until then it is UNKNOWN.
9. Every mark in the drum is derived from the same rows as the release ledger.
10. An UNKNOWN gap is drawn as a dashed pen lift labeled UNKNOWN, never a guess.
11. The drum's 60-day line matches the ledger's dormant rule (gap over 60 days).
12. The drum is legible in GitHub mobile rendering.
